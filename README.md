# نظام أرض العيينة المحاسبي

نظام محاسبي تشغيلي متكامل لمتابعة الحركة المالية لمشروع **أرض العيينة**: عهد المقاولين، التحويلات المالية، فواتير إخلاء العهد، وفواتير الموردين — مع ربط محاسبي كامل، دفتر أستاذ مزدوج، تقارير قابلة للتصدير، صلاحيات، وسجل عمليات.

> **ممنوع فيه الاختصار**: كل وحدة لها جدولها وخدماتها وواجهتها، وكل الأرصدة تُحتسب تلقائيًا من العمليات المسجلة (Data-Driven) — لا يوجد أي رقم مخزَّن يدويًا.

---

## التشغيل السريع

```bash
npm install                      # الاعتماديات (better-sqlite3 اختياري — يعمل بدونه)
cp .env.example .env             # ثم عدّل ADMIN_PASSWORD و SESSION_SECRET
npm run migrate                  # إنشاء القاعدة + البيانات المرجعية + حساب المدير
npm start                        # http://localhost:4000
```

بيانات الدخول الافتراضية من `.env` (`ADMIN_USERNAME` / `ADMIN_PASSWORD`) — **يجب تغييرها بعد أول دخول** (النظام يفرض `must_change_password`).

### بيئة تجريبية معزولة (Demo)

```bash
npm run seed:demo     # زرع سيناريوهات اختبار في data/demo/oyaynah-demo.db
npm run demo          # تشغيل الخادم على القاعدة التجريبية
```

بيئة Demo تستخدم **قاعدة بيانات منفصلة** وتُظهر شريط تحذير برتقاليًا في أعلى الواجهة.
قاعدة الإنتاج لا تحتوي على أي بيانات وهمية — فقط البيانات المرجعية (المشروع، مصادر التمويل، دليل الحسابات، الأدوار).

### الاختبارات

```bash
npm test              # 13 اختبار سيناريو على قاعدة مؤقتة
```

## السلسلة المحاسبية

```
مصدر التمويل ──▶ التحويل ──▶ العهدة ──▶ إخلاء العهدة
                    │
                    └──────▶ المورد ──▶ فاتورة المورد ──▶ الدفعة
```

كل عملية تحمل مفاتيح ربط تسمح بالانتقال في الاتجاهين، وكل عملية معتمدة تُولِّد قيدًا محاسبيًا متوازنًا تلقائيًا.

```
الرصيد المتبقي للعهدة = مبلغ العهدة − إجمالي فواتير الإخلاء المقبولة
```

## الوحدات

| الوحدة | الوصف |
|---|---|
| **لوحة التحكم** | 8 مؤشرات رئيسية + تحليل مصادر التمويل + رسوم + تنبيهات + آخر العمليات |
| **مصادر التمويل** | جاري الشريك، أوتك، النقليات — وقابلة للإضافة بدون تعديل الهيكل |
| **التحويلات** | ثلاثة أنواع: لعهدة مقاول / لمورد / أخرى، مع كشف التكرار وربط العهدة |
| **عهد المقاولين** | بطاقة كاملة: المصدر، التحويل، الإخلاءات، الرصيد، الحالة، المرفقات، السجل |
| **إخلاء العهد** | فواتير الإخلاء مع مراجعة واعتماد ومنع التجاوز إلا بصلاحية خاصة |
| **فواتير الموردين** | المدفوع والمتبقي وحالة السداد تلقائيًا |
| **الدفعات** | ربط الدفعات بالتحويلات والفواتير مع منع تجاوز المتبقي |
| **المقاولون / الموردون** | الرصيد الحقيقي لكل طرف + ملف كامل بحركته |
| **التقارير** | 11 تقريرًا مع تصدير Excel / CSV / PDF |
| **المطابقة** | 14 فحصًا لكشف العمليات غير المرتبطة والمكررة |
| **سجل العمليات** | كل الإضافة والتعديل والاعتماد بالبيانات القديمة والجديدة |
| **الإدارة** | المشاريع، مراكز التكلفة، دليل الحسابات، المستخدمون، الأدوار، الإعدادات |

## الأسئلة التي يجيب عليها النظام لحظيًا

| السؤال | أين |
|---|---|
| كم تم تحويله لمشروع أرض العيينة؟ | لوحة التحكم → إجمالي التحويلات |
| كم من جاري الشريك / أوتك / النقليات؟ | تحليل مصادر التمويل |
| كم إجمالي عهد المقاولين؟ | لوحة التحكم + تقرير العهد |
| كم تم إخلاؤه؟ | لوحة التحكم + تقرير الإخلاءات |
| كم رصيد العهد المفتوحة؟ | لوحة التحكم + تقرير الأرصدة |
| كم دُفع للموردين وكم المتبقي؟ | لوحة التحكم + تقرير الموردين |
| ما العمليات غير المطابقة؟ | تقرير المطابقة |
| ما الرصيد الحقيقي لكل مقاول؟ | تقرير المقاولين |

## الأدوار والصلاحيات

| الدور | الصلاحيات |
|---|---|
| **Administrator** | كل الصلاحيات (53) بما فيها المستخدمون والسجلات |
| **Accountant** | إضافة وتعديل وإلغاء العمليات + التقارير والتصدير (بدون اعتماد) |
| **Reviewer** | المراجعة والاعتماد + الموافقة على تجاوز رصيد العهدة |
| **Viewer** | العرض والتقارير والتصدير فقط |

مصفوفة الصلاحيات مخزَّنة في قاعدة البيانات وقابلة للتعديل من `إعدادات النظام ← الأدوار والصلاحيات`.

## الضوابط المحاسبية المطبَّقة

1. لا إخلاء يتجاوز قيمة العهدة إلا بصلاحية `settlements.over_settle` + تأكيد صريح (يُسجَّل في السجل).
2. لا تكرار لرقم فاتورة المورد (قيد فريد في القاعدة).
3. لا تكرار لرقم التحويل أو المرجع البنكي، وكشف التحويلات المطابقة.
4. مصدر التمويل إلزامي لكل تحويل.
5. المشروع إلزامي لكل عملية.
6. لا اعتماد لعملية ناقصة البيانات.
7. كل تعديل يُسجَّل بالبيانات القديمة والجديدة.
8. لا حذف نهائي — إلغاء (`is_void`) مع سبب.
9. الفواتير منفصلة عن التحويلات مع إمكانية الربط عبر الدفعات.
10. الأرصدة تُحدَّث تلقائيًا بعد كل عملية، والقيود تُعاد عند إلغاء الاعتماد.

## البنية التقنية

```
server/   Express + SQLite (WAL) — 15 خدمة، 4 مجموعات مسارات، migrations
public/   SPA عربية RTL بـ Vanilla JS (بلا إطار عمل ولا CDN) — Light/Dark
data/     oyaynah.db (الإنتاج) · demo/oyaynah-demo.db (التجريبي)
uploads/  المرفقات
tests/    اختبارات السيناريوهات
docs/     وثائق التصميم الثمانية
```

محرك قاعدة البيانات: يُستخدم `better-sqlite3` إن كان مثبَّتًا، وإلا `node:sqlite` المدمج في Node ≥ 22.5 —
فالنظام يعمل **بدون أي اعتمادية أصلية** (`server/db/driver.js`).
