# 01 · تحليل المتطلبات — نظام أرض العيينة المحاسبي

## 1. نطاق النظام

نظام محاسبي تشغيلي لمتابعة الحركة المالية لمشروع **أرض العيينة**، يدور حول أربعة كيانات مالية مترابطة:

| الكيان | الدور في الدورة المالية |
|---|---|
| مصدر التمويل | مصدر المال (جاري الشريك، أوتك، النقليات، …) |
| التحويل | حركة المال الفعلية من المصدر إلى المستفيد |
| عهدة المقاول | التزام على مقاول بمبلغ محدد ممولا بتحويل |
| إخلاء العهدة | فاتورة تُثبت صرف المقاول وتُنقص رصيد العهدة |
| فاتورة المورد | التزام على المشروع تجاه مورد |
| الدفعة | سداد فاتورة المورد من تحويل محدد |

## 2. السلسلة المحاسبية الإلزامية

```
مصدر التمويل ──▶ التحويل ──▶ العهدة ──▶ إخلاء العهدة
                    │
                    └──────▶ المورد ──▶ فاتورة المورد ──▶ الدفعة
```

لا توجد وحدة معزولة: كل عملية تحمل مفاتيح ربط (Foreign Keys) تسمح بالانتقال في الاتجاهين.

## 3. الأسئلة التي يجب أن يجيب عليها النظام في أي لحظة

| السؤال | المصدر في النظام |
|---|---|
| كم تم تحويله لمشروع أرض العيينة؟ | لوحة التحكم → إجمالي التحويلات |
| من أي مصدر تم التمويل؟ | تحليل مصادر التمويل |
| كم من جاري الشريك / أوتك / النقليات؟ | `funding_sources.analysis()` |
| كم إجمالي عهد المقاولين؟ | `advances.total` |
| كم تم إخلاؤه؟ | `settlements.total` (المعتمدة فقط) |
| كم رصيد العهد المفتوحة؟ | `advances.open_amount` |
| كم دُفع للموردين؟ | `suppliers.paid` |
| كم المتبقي للموردين؟ | `suppliers.due` |
| ما العمليات غير المطابقة؟ | تقرير المطابقة (14 فحصًا) |
| ما الرصيد الحقيقي لكل مقاول؟ | تقرير المقاولين |
| ما الرصيد الحقيقي لكل مصدر تمويل؟ | تقرير مصادر التمويل + دفتر الأستاذ |

## 4. القواعد المحاسبية الحاكمة

| # | القاعدة | مكان التنفيذ |
|---|---|---|
| 1 | الرصيد المتبقي = مبلغ العهدة − الإخلاءات **المعتمدة** | `advances.getBalance()` + view `v_advance_balances` |
| 2 | الإخلاءات المعلّقة لا تُنقص الرصيد لكنها تُحجز في «الرصيد المحتجز» | `settlements.create()` |
| 3 | لا إخلاء يتجاوز الرصيد المتاح إلا بصلاحية `settlements.over_settle` + تأكيد | `settlements.create()` |
| 4 | لا إغلاق لعهدة برصيد غير مسوَّى بدون تأكيد + صلاحية `advances.close` | `advances.close()` |
| 5 | مصدر التمويل إلزامي لكل تحويل | `transfers.validatePayload()` |
| 6 | المشروع إلزامي لكل عملية | كل الـ services |
| 7 | لا تكرار لرقم التحويل / المرجع البنكي / رقم فاتورة المورد | قيود UNIQUE + فحص مسبق |
| 8 | لا اعتماد لعملية ناقصة البيانات | `approve()` في كل service |
| 9 | لا حذف نهائي — إلغاء (`is_void`) مع سبب | كل الـ services |
| 10 | كل عملية معتمدة تُولّد قيدًا محاسبيًا متوازنًا | `ledger.post()` |
| 11 | كل تغيير يُسجَّل في سجل العمليات بالبيانات القديمة والجديدة | `audit.log()` |
| 12 | الدفعة لا تتجاوز المتبقي على الفاتورة ولا قيمة التحويل | `invoices.createPayment()` |

## 5. متطلبات غير وظيفية

- **Data-Driven**: لا يُخزَّن أي رقم مشتق؛ كل الرصيد يُحتسب من العمليات.
- **بدون بيانات وهمية**: قاعدة الإنتاج تُهيَّأ بالبيانات المرجعية فقط. البيانات التجريبية في قاعدة منفصلة (`data/demo/`) وتُظهر شريط تحذير في الواجهة.
- **RTL كامل** + دعم الوضع الليلي + تصميم متجاوب.
- **قابل للتوسعة**: إضافة مصدر تمويل أو مركز تكلفة أو مشروع جديد لا يتطلب أي تعديل في الهيكل.

## 6. الأدوار

| الدور | الصلاحيات الأساسية |
|---|---|
| Administrator | كل الصلاحيات (53 صلاحية) بما فيها المستخدمون والسجلات |
| Accountant | إنشاء وتعديل وإلغاء العمليات + التقارير والتصدير (بدون اعتماد) |
| Reviewer | المراجعة والاعتماد + الموافقة على تجاوز رصيد العهدة |
| Viewer | العرض والتقارير والتصدير فقط |
