# 08 · مسار المستخدم (User Flow)

## 1. الدخول

```
شاشة الدخول ← إدخال اسم المستخدم وكلمة المرور
   ├─ فشل → رسالة خطأ (وتُسجَّل المحاولة في سجل العمليات)
   └─ نجاح → تحميل /meta (مشاريع، مصادر، حسابات) → لوحة التحكم
```

## 2. الدورة الأساسية: عهدة مقاول

```
┌────────────────────────────────────────────────────────────────┐
│ 1) المحاسب: التحويلات ← «تحويل جديد»                            │
│    التاريخ · المبلغ 50,000 · المصدر: جاري الشريك               │
│    النوع: تحويل لعهدة مقاول · المقاول · المرجع البنكي · المشروع │
│    → حفظ (مسودة) أو حفظ + اعتماد                               │
│    ⚠ يظهر تحذير إن وُجد تحويل مطابق                            │
├────────────────────────────────────────────────────────────────┤
│ 2) المراجع: اعتماد التحويل                                      │
│    → يُولَّد القيد: 1200 عهدي المقاولين / 2100 جاري الشركاء      │
├────────────────────────────────────────────────────────────────┤
│ 3) المحاسب: العهد ← «عهدة جديدة»                                │
│    المقاول · المبلغ 50,000 · المصدر · التحويل المرتبط · البيان  │
│    → يظهر تحقق تلقائي من تطابق مبلغ التحويل مع مبلغ العهدة      │
├────────────────────────────────────────────────────────────────┤
│ 4) المراجع: اعتماد العهدة → الحالة: مفتوحة، الرصيد 50,000       │
├────────────────────────────────────────────────────────────────┤
│ 5) المحاسب: من بطاقة العهدة ← «إخلاء جديد»                      │
│    رقم الفاتورة · الصافي 20,000 · الضريبة · الحساب · المرفق     │
│    → يظهر الرصيد المتاح والرصيد بعد الإخلاء لحظيًا              │
├────────────────────────────────────────────────────────────────┤
│ 6) المراجع: مراجعة ← اعتماد                                     │
│    → الرصيد يصبح 30,000 · الحالة: مغلقة جزئيًا                  │
│    → قيد: 4110 مصاريف / 1200 عهدي المقاولين                     │
├────────────────────────────────────────────────────────────────┤
│ 7) تكرار الإخلاء حتى الرصيد صفر → الحالة: مغلقة تلقائيًا         │
│    أو إغلاق يدوي مع تأكيد + سبب (يُسجَّل في السجل)               │
└────────────────────────────────────────────────────────────────┘
```

## 3. الدورة الثانية: مورد

```
تحويل من أوتك (20,000) → فاتورة مورد (34,500) → اعتماد الفاتورة
   → قيد: 4120 مصاريف + 1400 ضريبة المدخلات / 2200 حسابات الموردين
→ دفعة 20,000 مرتبطة بالتحويل والفاتورة
   → المتبقي 14,500 · الحالة: مدفوعة جزئيًا
→ محاولة دفعة أكبر من المتبقي ← رفض 409 OVERPAYMENT
```

## 4. مسارات الرقابة

### تجاوز رصيد العهدة
```
إدخال إخلاء 12,000 على عهدة رصيدها 10,000
  ├─ بلا تأكيد → 409 OVER_SETTLEMENT + حوار يوضح الفرق
  ├─ تأكيد بلا صلاحية → 403 FORBIDDEN
  └─ تأكيد + صلاحية settlements.over_settle
       → يُسجَّل الإخلاء بـ over_settlement = 1
       → قيد إضافي في سجل العمليات (action = over_settle)
       → يظهر في تقرير المطابقة وفي شارة «تجاوز»
```

### المطابقة
```
تقرير المطابقة ← 14 فحصًا تلقائيًا
  → ملخص حسب الأهمية (عالية/متوسطة/منخفضة)
  → كل ملاحظة فيها زر يفتح البطاقة المرتبطة مباشرة
  → تصدير Excel للمراجع الخارجي
```

### سجل العمليات
```
أي إضافة/تعديل/اعتماد/إلغاء
  → سطر في audit_logs بالبيانات القديمة والجديدة (JSON)
  → زر «التفاصيل» يعرض جدول الفروقات (الحقل · قديم · جديد)
  → التطهير يتطلب صلاحية audit_logs.purge + تأكيدًا نهائيًا
```

## 5.矩阵 الصلاحيات في الواجهة

- الأزرار التي لا يملك المستخدم صلاحيتها **لا تظهر أصلًا**.
- `Store.can('advances.approve')` تتحكم في إظهار أزرار الاعتماد.
- حوار التجاوز يعرض checkbox التأكيد فقط لمن يملك الصلاحية، وإلا يعرض رسالة مراجعة.

## 6. البحث والانتقال

```
البحث الشامل (الشريط العلوي)
  → نتائج مجمّعة من 8 وحدات
  → النقر ينقل للسجل مباشرة

من أي بطاقة يمكن الانتقال إلى:
  العهدة ←→ التحويل ←→ الإخلاءات ←→ الفاتورة ←→ الدفعة ←→ المقاول/المورد
```

## 7. التصدير

```
Excel  → /api/export/:key/xlsx  (ورقة RTL، رأس ملوّن، تجميد الصفوف، AutoFilter، صف إجماليات)
CSV    → /api/export/:key/csv   (BOM لدعم العربية في Excel)
PDF    → /api/print/:key        (صفحة A4 عرضية جاهزة للطباعة/الحفظ كـ PDF بدعم عربي كامل)
```

## 8. سيناريو المستخدم الأول (تشغيل فعلي)

```
1. npm install
2. cp .env.example .env   ← غيّر ADMIN_PASSWORD و SESSION_SECRET
3. npm run migrate        ← إنشاء القاعدة + البيانات المرجعية + حساب المدير
4. npm start              ← http://localhost:4000
5. سجّل الدخول → غيّر كلمة المرور
6. أضف المقاولين والموردين (البيانات المرجعية)
7. ابدأ بتسجيل التحويلات ثم العهد

للتجربة ببيانات جاهزة (معزولة تمامًا):
   npm run seed:demo  ثم  npm run demo
```
